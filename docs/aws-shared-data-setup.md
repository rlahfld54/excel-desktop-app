# AWS Shared Data Setup

This project is currently a desktop-first Electron app with local SQLite. For a 2-10 person shared-data setup, keep SQLite for local/offline backup and add a small AWS API for shared records.

## Recommended Runtime

- Electron app stays installed on each PC.
- Shared data is read through API Gateway HTTP API and Lambda.
- PostgreSQL on RDS stores shared business records.
- S3 stores end-of-day backup files.
- The app checks for shared changes every 60 seconds.

## Environment Variables

Copy `.env.example` to `.env.local` and fill these values after the AWS API exists.

```env
VITE_SHARED_API_BASE_URL=https://example.execute-api.ap-northeast-2.amazonaws.com
VITE_SHARED_API_KEY=
VITE_SHARED_POLLING_INTERVAL_MS=60000
VITE_SHARED_API_TIMEOUT_MS=15000
VITE_SHARED_BACKUP_BUCKET=excel-desktop-backups
VITE_SHARED_BACKUP_REGION=ap-northeast-2
```

Do not commit `.env.local`.

## First Shared Tables

Start with only the data that must be shared by multiple users.

1. contacts
2. closing_companies
3. todo_items
4. app_events
5. backup_history

The first PostgreSQL draft is in `aws/schema.sql`.

Keep local settings, UI preferences, temporary upload previews, and local backup manifests on the PC.

## Migration Notes

- Convert SQLite `INTEGER PRIMARY KEY AUTOINCREMENT` to PostgreSQL `GENERATED BY DEFAULT AS IDENTITY`.
- Convert JSON text columns to `jsonb` when the value is queried or filtered.
- Add `created_by`, `updated_by`, `created_at`, `updated_at`, and `version` to shared tables.
- Use `version` or `updated_at` to detect conflicts when two people edit the same row.
- Keep S3 backup separate from RDS. S3 is for files, not live SQL queries.

## Cost-Safe Defaults

- Use 60 second polling first.
- Do not use Redis or WebSocket unless sub-minute updates become necessary.
- Do not add NAT Gateway for this small setup unless there is a specific network requirement.
- Use `db.t4g.micro` first, then scale to `db.t4g.small` only if the app becomes slow.
