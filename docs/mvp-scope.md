# MVP 범위

## 제품 목표

이 앱의 1차 MVP는 "총무팀 매출 마감 검수"를 위한 로컬 우선 데스크톱 작업 공간이다.

핵심 목표는 엑셀 파일을 예쁘게 보여주는 것이 아니라, 마감 직전 반복되는 검수와 확인 요청 업무를 줄이는 것이다.

사용자는 다음 흐름을 앱 안에서 처리할 수 있어야 한다.

1. Excel 또는 CSV 매출 파일을 업로드한다.
2. 업로드 데이터를 기준 데이터와 비교한다.
3. 오류, 중복, 단가 불일치, 금액 불일치를 모은다.
4. 사람이 승인, 보류, 수정 필요 상태를 부여한다.
5. 최종 보고서 또는 거래처 확인 요청 패키지를 만든다.
6. 작업 기록과 검증 이력을 SQLite에 남긴다.

## MVP에 포함하는 것

### 데이터 업로드

- CSV/XLSX 업로드
- 첫 번째 시트 또는 첫 번째 데이터 테이블 로드
- 업로드 파일명, 행 수, 열 수 기록
- 최근 파일 목록 기록

### 매출 검증

- 거래처 코드 존재 여부 확인
- 제품 코드 존재 여부 확인
- 기준 단가와 업로드 단가 비교
- 수량 곱하기 단가와 매출액 비교
- 중복 행 검출
- 대량 거래와 고액 거래 확인
- 오류 목록 생성

### 기준 데이터

- 거래처 기준 데이터
- 제품 기준 데이터
- 영업 단가 기준 데이터
- 거래처/제품 별칭 데이터
- 기준 데이터 변경 이력
- 변경 전후 백업 기록

### 오류 처리

- 행 선택
- 선택 행 상세 표시
- 승인, 보류, 수정 필요 처리
- 오류 상태 변경
- 오류 처리 로그 기록
- 개인 담당자보다 부서 단위 추적

### 보고서

- 검증 결과 보고서 초안
- 거래처별 오류 목록
- PDF/XLSX 내보내기 기반 구조
- 보고서 생성 작업 이력

### 요청 센터

- 거래처별 확인 요청 목록
- 연락처 목록
- 이메일/카톡 문구 템플릿
- 발송 패키지 생성
- send_list.csv 생성 기반
- 첨부 폴더 정리 기반
- 발송 완료 수동 체크

### 로컬 저장

- SQLite 기반 로컬 데이터 저장
- workspace snapshot 저장
- sales upload 저장
- sales rows 저장
- validation issues 저장
- validation summary 저장
- app events 저장

## MVP에서 제외하는 것

### 직접 대량 발송

앱 본체에서 Gmail, Outlook, SMTP, 카카오톡 자동 발송을 직접 수행하지 않는다.

이유:

- 인증과 보안 부담이 크다.
- 스팸 처리 리스크가 있다.
- 실패 재시도와 발송 추적이 무거워진다.
- 카카오톡 자동화는 정책과 계정 리스크가 있다.

대신 앱은 발송 준비를 완벽하게 해주는 "발송 패키지 생성기" 역할을 한다.

### 복잡한 로그인

초기 MVP에서는 완성형 로그인/권한 시스템을 만들지 않는다.

대신:

- 로컬 관리자 모드
- users 테이블
- departments 테이블
- login_logs 테이블

정도만 준비해둔다.

### 창고, 재고, BOM

총무팀 매출 마감 검수 범위를 벗어나는 창고, 재고, BOM 관리는 1차 MVP에서 제외한다.

## 성공 기준

MVP는 다음이 가능하면 성공으로 본다.

- 1,000행 이상의 매출 데이터를 업로드하고 볼 수 있다.
- 검증 규칙으로 오류 목록을 만들 수 있다.
- 오류 행을 사람이 처리할 수 있다.
- 처리 결과가 SQLite에 저장된다.
- 거래처별 확인 요청 패키지 구조를 만들 수 있다.
- 보고서와 발송 준비 흐름이 화면에서 자연스럽게 이어진다.

## 우선순위

1. 업로드와 테이블 표시
2. 검증 규칙
3. 오류 처리
4. SQLite 저장
5. 보고서 생성
6. 요청 센터 패키지
7. 백업/복원
8. 권한/로그인
