1. 기준 데이터는 자주 변경되면 안 된다

영업 단가, 제품 코드, 거래처 코드, 거래처명, 날짜 형식, 숫자 단위 등은
업무 전체의 기준이 되는 데이터다.

이 데이터가 자주 변경되면:

기존 보고서와 결과값이 달라질 수 있고,
부서 간 데이터 불일치가 발생하며,
거래처 및 ERP 데이터와 충돌할 가능성이 높아진다.

따라서 기준 데이터는:

승인 없이 변경되지 않아야 하며,
변경 시 변경 이력을 반드시 남겨야 한다.

또한:

변경 전/후 데이터를 자동 백업해야 하며,
최소 3년 이상 보관 가능해야 한다.

이는 단순 기능 문제가 아니라:

감사 대응,
회계 검증,
거래 이력 추적,
문제 발생 시 원인 분석

을 위해 반드시 필요한 구조다.

2. 데이터 비교는 “이름”이 아니라 코드 기준이어야 한다

사람은 거래처명을 보고 데이터를 이해하지만,
시스템은 거래처명으로 비교하면 안 된다.

예를 들어:

삼성
삼성전자
(주)삼성전자
삼성전자(본사)

처럼 동일 거래처라도 입력 방식이 다를 수 있다.

따라서:

거래처 코드
제품 코드
내부 인덱스
고유 식별값

기준으로 빠르게 매핑해야 한다.

거래처명은:
“사람이 보기 쉽게 보여주는 표시용 데이터”
에 가깝다.

실제 비교 및 검증은:
코드 기반으로 처리되어야 한다.

3. 기존 데이터가 정리되지 않은 회사가 대부분이다

현실적으로 새로운 시스템을 도입할 때,
이미 데이터가 잘 정리되어 있는 회사는 거의 없다.

오히려:

거래처명 규칙이 제각각이거나,
코드 체계가 중복되거나,
엑셀 서식이 부서마다 다르거나,
사람이 직접 수정한 데이터가 섞여 있는 경우가 많다.

그래서 시스템은:
“완벽하게 정리된 데이터만 받는 구조”
가 아니라,

“정리되지 않은 데이터도 점진적으로 표준화할 수 있는 구조”
여야 한다.

예를 들어:

거래처 자동 추천 매핑
유사 거래처 탐지
코드 자동 연결 제안
잘못된 형식 자동 수정
사용자 승인 기반 정제

같은 기능이 필요하다.

실제 현업에서:
새로운 시스템 도입이 실패하는 가장 큰 이유 중 하나는
“기존 방식과 데이터를 강제로 바꾸려고 하기 때문”
이다.

따라서:
기존 데이터를 최대한 유지하면서,
조금씩 표준화할 수 있도록 도와주는 방향이 중요하다.
